# База данных и API

## Таблицы базы данных

### `user`

| Столбец | Тип | NULL | Описание |
|---|---|---:|---|
| `id` | identity / integer | Нет | Первичный ключ; значение генерируется базой данных |
| `login` | `text` | Нет | Логин; уникальный |
| `password_hash` | `text` | Нет | Хеш пароля |

**Ограничения и связи:**
- Уникальное ограничение на `login`.
- Один пользователь может иметь несколько изотопов и лайков.

### `isotope`

| Столбец | Тип | NULL | Описание |
|---|---|---:|---|
| `id` | identity / integer | Нет | Первичный ключ; значение генерируется базой данных |
| `name` | `text` | Нет | Название изотопа |
| `description` | `text` | Да | Описание |
| `image_url` | `text` | Да | Ключ изображения в MinIO |
| `video_url` | `text` | Да | Ключ видео в MinIO |
| `half_life` | `numeric` | Да | Период полураспада; в приложении преобразуется в `bigint` |
| `is_alpha` | `boolean` | Да | Признак альфа-излучения |
| `status` | `smallint` | Нет | Статус изотопа; по умолчанию `Draft` (`0`) |
| `author_id` | тип столбца задаётся связью | Нет | Внешний ключ на `user.id` |
| `created_at` | `timestamptz` | Нет | Дата создания; по умолчанию текущее время |
| `published_at` | `timestamptz` | Да | Дата публикации |

Значения `status`:
- `0` — `Draft` (черновик)
- `1` — `Published` (опубликован)
- `2` — `Deleted` (удалён)

**Ограничения и связи:**
- `status` должен быть одним из значений `0`, `1` или `2`.
- Для `half_life` задано условие `"half_life" > 0`. В SQL `NULL` проходит проверку `CHECK`, поэтому столбец при этом остаётся nullable.
- Каждый изотоп связан с одним автором (`author_id` → `user.id`).
- У изотопа может быть несколько лайков.

### `like`

| Столбец | Тип | NULL | Описание |
|---|---|---:|---|
| `id` | identity / integer | Нет | Первичный ключ; значение генерируется базой данных |
| `user_id` | тип столбца задаётся связью | Нет | Внешний ключ на `user.id` |
| `isotope_id` | тип столбца задаётся связью | Нет | Внешний ключ на `isotope.id` |

**Ограничения и связи:**
- Уникальная пара `(user_id, isotope_id)`: пользователь может поставить изотопу не более одного лайка.
- Удаление лайка выполняется удалением строки из таблицы `like`.

## API

Все маршруты указаны без глобального префикса `/api`.

### Пользователи

| Метод и путь | Описание |
|---|---|
| `POST /users` | Регистрация пользователя. Принимает JSON-тело `RegisterDTO`; сервис нормализует логин &mdash; удаляет пробелы по краям и приводит к нижнему регистру. Возвращает представление пользователя. Если логин уже занят, возвращает конфликт. |
| `POST /users/auth` | Заглушка входа: пока возвращает `{}`. |
| `POST /users/logout` | Заглушка выхода: пока возвращает `{}`. |

### Изотопы

| Метод и путь | Описание |
|---|---|
| `GET /isotopes` | Возвращает опубликованные изотопы. Необязательный query-параметр `maxHalfLifeExponent` &mdash; целое число не меньше `0`; при его наличии результат ограничивается условием `half_life <= 10^maxHalfLifeExponent`. Ответ содержит `isotopes` и `maxHalfLifeExponent`; если параметр не передан, в ответе используется `-1`. |
| `POST /isotopes` | Создаёт черновик текущего пользователя. Запрос обрабатывается как `multipart/form-data`: поля формы соответствуют `IsotopeDraftDTO`, файлы `video` и `image` необязательны; для каждого поля принимается не более одного файла. При уже существующем черновике возвращается конфликт. |
| `GET /isotopes/draft` | Возвращает черновик текущего пользователя или `null`, если черновика нет. |
| `PUT /isotopes/draft` | Публикует черновик текущего пользователя. Принимает JSON-тело `IsotopePublishDTO`. Если черновик не найден, возвращает `404`. |
| `DELETE /isotopes/:id` | Переводит опубликованный изотоп текущего пользователя в статус `Deleted`, удаляет связанные медиафайлы из MinIO и возвращает представление изотопа. Если подходящий изотоп не найден, возвращает `404`. |
| `POST /isotopes/:id/like/:action` | Добавляет или удаляет лайк текущего пользователя. `:action` соответствует `LikeAction`: `0` &mdash; `Remove`, `1` &mdash; `Add`. Повторное добавление не создаёт дубликат. Возвращает `isLiked` и `likeCount`. Если изотоп не опубликован или не найден, возвращает `404`. |

### Лента изотопов

| Метод и путь | Описание |
|---|---|
| `GET /isotopes/feed` | Возвращает первый опубликованный изотоп по возрастанию `id` или `null`, если опубликованных изотопов нет. |
| `GET /isotopes/feed/:id` | Возвращает опубликованный изотоп с указанным `id`. |
| `GET /isotopes/feed/:id?next=true` | Возвращает следующий опубликованный изотоп с `id`, большим указанного. Если следующего нет, возвращает первый опубликованный изотоп. Если подходящий изотоп в итоге не найден, возвращает `404`. |

## Примечание об идентификации пользователя

В показанном коде `AuthService.getCurrentUserId()` всегда возвращает `2`. Поэтому вызовы, обозначенные как действия «текущего пользователя», пока фактически выполняются от имени пользователя с `id = 2`; полноценная аутентификация ещё не реализована.
